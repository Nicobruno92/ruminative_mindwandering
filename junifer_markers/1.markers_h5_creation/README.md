# Pipeline 1: H5 Markers Creation with SLURM Array Batches

This pipeline processes EEG data from BIDS-formatted derivatives to create HDF5 marker files using Junifer with SLURM array job parallelization.

## Overview

The pipeline computes multiple EEG features (spectral power, connectivity, information theory metrics, and ERP topographies) from epoched FIF files and stores them in HDF5 format. It uses SLURM array jobs to process multiple subjects/tasks in parallel on a compute cluster.

## Pipeline Components

### 1. Configuration File (`config.yaml`)
Defines the complete Junifer pipeline including:
- **DataGrabber**: Pattern-based file discovery from BIDS derivatives
- **DataReader**: SARTDataReader with behavioral parameter extraction
- **Storage**: HDF5FeatureStorage for output
- **Markers**: 
  - Spectral Power (absolute & relative)
  - Symbolic Mutual Information (connectivity)
  - Permutation Entropy
  - Kolmogorov Complexity
  - Time-Locked Topographies (P1, N1, P2, P3a, P3b)

### 2. SLURM Array Script (`slurm_array_junifer.sh`)
Main SLURM job script that:
- Maps SLURM_ARRAY_TASK_ID to elements from elements file
- Activates conda environment
- Sets optimal threading parameters for cluster
- Runs junifer for a single element (subject/task/desc combination)

### 3. Submission Helper (`submit_slurm_array.sh`)
Orchestrates the job submission:
- Optionally generates elements file via `junifer queue`
- Counts elements and determines array size
- Submits array job with proper dependencies
- Can optionally chain collection and PKL creation jobs

## Usage

### Basic Usage (On Cluster)

1. **Prepare workspace**:
   ```bash
   cd /network/iss/home/nicolas.bruno/Junifer
   mkdir -p logs
   ```

2. **Generate elements and submit**:
   ```bash
   ./junifer_markers/pipeline_1_h5_creation/submit_slurm_array.sh --queue
   ```

3. **Monitor jobs**:
   ```bash
   squeue -u $USER
   watch squeue -u $USER
   ```

4. **Check logs**:
   ```bash
   tail -f logs/CYBERSART_features_*.out
   ```

### Advanced Usage

**Customize resources**:
```bash
CPUS=8 MEM=16G TIME=12:00:00 ./submit_slurm_array.sh --queue
```

**Use specific partition**:
```bash
PARTITION=high-memory ./submit_slurm_array.sh --queue
```

**Submit without regenerating elements**:
```bash
./submit_slurm_array.sh
```

**Disable PKL creation chain**:
```bash
CREATE_PKL=no ./submit_slurm_array.sh --queue
```

**Force overwrite existing HDF5 file**:
```bash
OVERWRITE=yes ./submit_slurm_array.sh --queue
```

**Manually delete HDF5 file before rerunning**:
```bash
./clean_h5.sh  # or manually: rm /network/iss/cenir/analyse/meeg/CYBERSART/BIDS/features/junifer/markers.h5
```

### Direct SLURM Submission

If you already have an elements file:
```bash
# Count elements
N=$(wc -l < junifer_jobs/CYBERSART_features/elements)
END=$((N - 1))

# Submit array
sbatch --array=0-${END} \
       --cpus-per-task=4 \
       --mem=8G \
       --time=08:00:00 \
       junifer_markers/pipeline_1_h5_creation/slurm_array_junifer.sh
```

| `OVERWRITE` | `no` | Delete existing HDF5 file before submission |

## Resource Recommendations

### Per-Element Resources
- **CPUs**: 4 (optimal for I/O and light computation)
- **Memory**: 8GB (sufficient for most subjects)
- **Time**: 8 hours (conservative, most finish in 2-4h)

### For Large Cohorts
If you have 168 elements (168 subject/task pairs):
- Array size: 0-167
- Total walltime: ~8 hours (all parallel)
- Cluster resources: 168 × 4 = 672 CPUs, 168 × 8GB = 1.3TB memory

## Troubleshooting

### Common Issues

#### Issue 1: "Duplicate element ... skipping store"
**Symptom**: Jobs complete but log shows "skipping store" for all markers
```
2025-10-15 19:48:26,316 - JUNIFER - INFO - Duplicate element: {'subject': 'sub-22', 'task': 'Sart3', 'desc': 'state'} found for 8745fbb100646dce9a174ab2213c0dbf, skipping store ...
```

**Cause**: The elements file contains duplicate entries. Junifer computes features but refuses to store them.

**Solution**:
```bash
# Use the management script
bash junifer_markers/1.markers_h5_creation/manage_pipeline.sh full

# Or manually
python junifer_markers/1.markers_h5_creation/manage_elements.py fix
```

#### Issue 2: "The following element selectors are invalid"
**Symptom**: Job fails immediately with error
```
RuntimeError: The following element selectors are invalid:
{('sub-14', 'Sart1', 'state')}
```

**Cause**: The element exists in the elements file but the corresponding derivative file doesn't exist.

**Solution**:
```bash
# Use the management script
bash junifer_markers/1.markers_h5_creation/manage_pipeline.sh full

# Or manually
python junifer_markers/1.markers_h5_creation/manage_elements.py fix
```

### Other Issues

#### Jobs Failing
1. Check logs: `logs/CYBERSART_features_*_*.err`
2. Common issues:
   - Missing input files → verify BIDS structure
   - Memory errors → increase `MEM`
   - Timeout → increase `TIME`

#### Missing Elements
```bash
# Regenerate elements file
junifer queue config.yaml --overwrite --verbose info
```

#### Conda Environment Issues
```bash
# Test activation manually
conda activate junifer
python -c "import junifer; print(junifer.__version__)"
```

#### Re-run Failed Jobs
```bash
# Get list of failed array IDs
sacct -j <JOB_ID> --format=JobID,State | grep FAILED

# Re-submit only failed indices
sbatch --array=5,12,23 slurm_array_junifer.sh
```

## Integration with Pipeline 2

This pipeline produces HDF5 files that are consumed by Pipeline 2 (PKL creation). The submission script can automatically chain both pipelines using SLURM dependencies:

```bash
# Automatic chaining (default)
./submit_slurm_array.sh --queue

# This submits:
# 1. Array job (H5 creation)
# 2. Collection job (after array completes)
# 3. PKL job (after collection completes)
```

## Notes

- The pipeline uses `single_output: false` in storage config, meaning all features are stored in one HDF5 file
- Element metadata is embedded in each feature for later retrieval
- The pipeline respects BIDS naming conventions
- Threading is constrained to avoid cluster contention (OMP_NUM_THREADS=1, etc.)
- MNE logging is set to WARNING to reduce output volume
