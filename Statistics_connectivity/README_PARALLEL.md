# Parallel Connectivity Analysis

## Overview

This pipeline leverages cluster parallelism to run connectivity analyses efficiently:

- **Sequential mode**: Processes 4 bands one after another (~8-12 hours)
- **Parallel mode**: Processes 4 bands simultaneously (~2-3 hours)

## Execution Modes

### 1. Sequential Execution (Original)

Processes all bands in a single job:

```bash
sbatch Statistics_connectivity/run_lmm_connectivity_slurm.sh
```

**Pros**: Simple, single job to monitor  
**Cons**: Slower (sequential processing)

### 2. Parallel Execution (Recommended)

Submits array job for bands + aggregation job:

```bash
bash Statistics_connectivity/submit_parallel_connectivity.sh
```

This creates:
- **Array job** (4 tasks): One per band (theta, alpha, beta, gamma)
- **Aggregation job**: Combines results and generates multi-band figures

**Pros**: 4x faster, efficient cluster usage  
**Cons**: Multiple jobs to monitor

### 3. Partial Parallel Execution

Run only specific bands:

```bash
# Only theta and alpha
bash Statistics_connectivity/submit_parallel_connectivity.sh --bands "0-1"

# Only beta
bash Statistics_connectivity/submit_parallel_connectivity.sh --bands "2"
```

Band indices:
- 0 = theta
- 1 = alpha
- 2 = beta
- 3 = gamma

## Monitoring

```bash
# Check job status
squeue -u $USER

# Monitor array job output (replace JOBID)
tail -f logs/connectivity_band_JOBID_0.out  # theta
tail -f logs/connectivity_band_JOBID_1.out  # alpha
tail -f logs/connectivity_band_JOBID_2.out  # beta
tail -f logs/connectivity_band_JOBID_3.out  # gamma

# Monitor aggregation job
tail -f logs/connectivity_aggregate_JOBID.out
```

## Resource Allocation

### Per-band job (array task):
- **CPUs**: 8 (for NBS permutations with joblib)
- **Memory**: 32 GB
- **Time**: 6 hours
- **Total cluster usage**: 4 × 8 = 32 CPUs simultaneously

### Aggregation job:
- **CPUs**: 4
- **Memory**: 16 GB
- **Time**: 2 hours

## Configuration

### Enable NBS for final analysis

Edit `config.yaml`:

```yaml
correction:
  roi: "fdr"
  channel: "nbs"  # Change from "fdr" to "nbs"

nbs:
  n_permutations: 1000  # Or 5000 for publication
  n_jobs: -1  # Use all available CPUs
```

### Adjust parallelism

```yaml
nbs:
  n_jobs: 8   # Fixed number of CPUs
  n_jobs: -1  # Use all available (reads SLURM_CPUS_PER_TASK)
  n_jobs: 1   # Sequential (for debugging)
```

## Troubleshooting

### OOM (Out of Memory) errors

1. Use FDR instead of NBS for testing:
   ```yaml
   correction:
     channel: "fdr"
   ```

2. Reduce permutations:
   ```yaml
   nbs:
     n_permutations: 500  # Instead of 1000
   ```

3. Increase memory allocation in `submit_band_array.sh`:
   ```bash
   #SBATCH --mem=64G  # Instead of 32G
   ```

### Job dependencies not working

Check job status:
```bash
squeue -u $USER
sacct -j JOBID --format=JobID,State,ExitCode
```

If aggregation job shows `DependencyNeverSatisfied`, one of the array tasks failed. Check logs.

### Missing results

Ensure all band jobs completed successfully before aggregation runs:
```bash
sacct -j ARRAY_JOBID --format=JobID,State,ExitCode
```

All tasks should show `COMPLETED` with `ExitCode 0:0`.

## Performance Comparison

| Mode | Bands | Time | Cluster CPUs | Total CPU-hours |
|------|-------|------|--------------|-----------------|
| Sequential | 4 | ~8h | 8 | 64 |
| Parallel | 4 | ~2h | 32 | 64 |

**Note**: Total CPU-hours are the same, but wall-clock time is 4× faster with parallel mode.
